# dual-ai

OpenRig로 실제 Codex와 Claude Code CLI를 함께 운영한다. 이 배포물은 실행 파일이나 OpenRig 포크가 아닌 에이전트용 작업 지침이다. Codex는 디자인·프론트엔드, Claude Code는 백엔드·서버 로직을 책임지며, 양쪽 모두 하위 에이전트와 저장된 스킬을 활용할 수 있다.

## 활성화 범위

- 사용자가 `$dual-ai` 또는 `dual-ai`를 명시하여 실제 작업에 적용해 달라고 요청했을 때만 실행한다. 일반적인 OpenRig 요청, 작업 난도, 병렬 처리 필요성만으로 활성화하지 않는다.
- 스킬 설명·생성·수정·상태 확인 요청, 인용문이나 외부 자료에 등장한 이름은 작업 팀 실행 요청이 아니다.
- 명시적으로 활성화한 동일 작업의 후속 수정과 검증은 활성 상태를 이어간다. 하위 에이전트마다 사용자에게 호출을 반복하게 하지 않는다. 별개의 새 작업으로 자동 이월하지 않으며, 사용자가 중단하거나 단일 AI로 전환하면 혼합 위임을 멈춘다.
- 이 스킬을 호출하지 않은 일반 작업에서는 Codex가 수행하고, Claude Code를 병행 실행하거나 Claude API로 우회 위임하지 않는다.

## 역할과 병렬 구성

| 책임자 | 기본 담당 | 같은 도구를 사용하는 하위 에이전트의 예 |
| --- | --- | --- |
| Codex 리드 (`runtime: codex`) | 디자인, UI/UX, 프론트엔드 구현, 반응형, 접근성, 화면 검증 | 화면·컴포넌트 구현, 스타일·상호작용, 프론트엔드 검증 |
| Claude Code 리드 (`runtime: claude-code`) | 서버 구조, API, 데이터베이스, 인증, 백엔드 로직과 테스트 | API·서비스 구현, 데이터·인증, 백엔드 검증 |

- 프론트엔드 코드 작성도 Codex가 맡는다. 사용자가 구체적으로 배정을 바꾸면 그 배정을 따른다.
- 각 리드는 독립적인 하위 작업이 있으면 자신의 하위 에이전트를 두고 병렬로 위임한다. 작업량과 실행 환경의 동시 실행 한도에 맞춰 필요한 수만 사용한다. 의존성이 있는 단계는 순서대로 진행한다.
- OpenRig의 하위 작업석(seat)과 `delegates_to` 관계로 책임자와 작업자를 구성할 수 있다. 해당 도구가 네이티브 하위 에이전트를 지원하면 그 기능도 활용할 수 있다. 지원 여부를 확인하고 실제 사용한 방식을 구분해 보고한다.
- Codex 하위 작업자는 Codex로, Claude Code 하위 작업자는 Claude Code로 실행한다. 이 세션의 Codex 하위 에이전트에 Claude라는 이름만 붙인 것을 Claude Code 실행으로 취급하지 않는다.
- 각 위임에는 목표, 담당 파일·폴더, 입력·출력, 완료 조건, 사용할 수 있는 스킬의 위치, 결과를 받을 책임자를 전달한다. 각 리드는 하위 결과를 검토하고 통합한다.
- 양쪽은 먼저 API 요청·응답 형식과 공통 타입을 맞춘다. 같은 파일을 동시에 수정하지 않도록 담당 범위를 나누며, 공통 설정·의존성·스키마 변경은 책임자를 정해 조율한다. 병렬 수정 충돌이 예상되면 분리된 작업 공간을 사용한다.

## 저장된 스킬 활용

- 두 리드와 모든 하위 에이전트는 자신의 도구에 저장된 전역·프로젝트 스킬과 활성 플러그인의 스킬을 작업에 맞게 자유롭게 선택해 사용한다. 스킬 사용 자체를 매번 사용자에게 다시 승인받거나 역할 표에 나온 일부 스킬로만 제한하지 않는다.
- 실제 제공된 스킬 목록과 `SKILL.md`를 확인한다. Codex는 전역 Codex·공유 스킬과 프로젝트의 `.agents/skills` 등을, Claude Code는 전역·프로젝트 `.claude/skills`와 활성 플러그인 스킬 등을 확인한다. 스킬별 명시 호출 전용 정책과 작업·권한 범위는 존중한다.
- 하위 에이전트에게 필요한 스킬 이름과 읽을 수 있는 경로를 전달한다. 부모의 스킬이 자동으로 상속된다고 가정하지 말고, OpenRig AgentSpec의 스킬 선택·리소스 전달이나 실제 경로 접근으로 제공한다.
- 스킬 루트는 각 도구의 실제 환경에서 찾는다. Codex는 `CODEX_HOME`이 설정돼 있으면 그 아래의 `skills`, 아니면 `~/.codex/skills`와 `~/.agents/skills`를 확인한다. Claude Code는 `~/.claude/skills`와 프로젝트·활성 플러그인의 스킬을 확인한다. Windows와 WSL은 홈 디렉터리와 설정이 서로 다르므로 실행 위치에서 실제로 읽을 수 있는 절대 경로를 전달한다. 공유한 Windows 경로는 `wslpath` 등 실행 환경의 경로 변환 도구로 변환하고 존재 여부를 확인한다.
- Windows에 저장된 스킬을 WSL에서 읽을 수 있다는 사실과 그 스킬의 실행 도구·인증·연결이 WSL에서 사용 가능하다는 사실을 구분한다. 상대 경로는 스킬 폴더를 기준으로 해석하고, Windows 전용 실행 파일은 지원되는 실행 경로를 확인한다. 없는 도구나 연결은 있다고 가정하지 않으며, 기존 스킬을 통째로 복사하거나 덮어쓰지 않는다.
- 디자인 작업은 현재 사용자의 전역·프로젝트 디자인 지침과 기존 브랜드·프레임워크를 따른다. 이 스킬은 특정 디자인 스킬이나 UI 라이브러리를 필수로 설치하지 않는다. 각 담당자는 작업에 필요한 전문 스킬만 선택한다.
- 스킬 사용은 외부 메시지 발송·배포·결제·계정 권한 변경 등에 대한 포괄적 승인이 아니다. 해당 작업에 필요한 기존 사용자 승인과 제한을 유지한다.

## OpenRig 실행과 검증

1. 사용자의 작업 목표, 프로젝트 경로, 완료 조건을 파악한다. 이미 주어진 정보는 다시 묻지 않는다. 공식 OpenRig `rigs` 스킬이 설치돼 있으면 읽고 현재 버전의 시작·운영자 전달 절차를 따른다. 없으면 이 배포물에 포함된 것으로 가정하지 말고 [공식 설치 안내](https://github.com/mvschwarz/openrig#install-and-first-run)에서 설치 경로를 확인한다. 공식 스킬 설치나 팀 시작이 필요하면 구체적인 변경 내용을 설명하고 현재 요청의 권한 범위 안에서 진행한다. 이 문서에는 역할, 명시 호출 조건, 병렬 위임에 대한 사용자의 선택이 담겨 있으므로 운영자와 리드에게 함께 전달한다.
2. OpenRig가 설치된 실제 macOS·Linux·WSL2 환경에서 실행한다. Windows에서는 사용자가 선택한 WSL 배포판·Linux 사용자를 먼저 확인하고 그 환경 안에서 작업한다. 특정 배포판 이름, 사용자명, 홈 디렉터리나 프로젝트 경로를 가정하지 않는다. Windows 프로젝트 경로를 공유할 때는 WSL 경로로 변환해 실제 디렉터리를 확인한다.
3. `rig --version`, `claude auth status`, `codex login status`로 현재 설치와 로그인을 확인한다. Claude Code는 연결된 구독 계정을 기본으로 사용하고, API 키 과금으로 임의 전환하지 않는다. 자격 증명을 출력하거나 복사하지 않는다.
4. 기존 팀과 설정을 확인한 뒤 현재 설치 버전의 도움말·문서에 맞춰 팀 구성을 만든다. 두 리드와 필요한 하위 작업자들의 실제 런타임, 작업 경로, 스킬 전달, 위임 관계를 명시한다. 제공자를 둘 다 등록한 것만으로 역할 분담이나 하위 팀이 생겼다고 보고하지 않는다.
5. 팀 시작 전 구체적인 구성과 개인 설정·프로젝트 파일에 미치는 변경을 알리고, 공식 `rigs`와 현재 환경의 시작 승인 절차를 따른다. 같은 구성의 시작을 이미 승인받았다면 다시 묻지 않는다. 스킬 호출 자체가 권한 우회·자동 승인·모든 후속 작업의 승인은 아니다.
6. 실제 프로젝트 작업은 OpenRig 운영자를 통해 팀에 전달한다. 목표와 완료 조건을 작업 큐에 기록하고, 각 작업자의 상태·결과·후속 위임을 끝까지 확인한다. 검토·통합 책임은 각 리드와 최종 조정자에게 있다.
7. 필요한 빌드·테스트·화면 검증을 수행하고 실제 변경 결과를 확인한다. 로그인이 정상이라는 이유만으로 작업 완료나 두 도구의 실제 실행 성공을 주장하지 않는다. 한쪽이 한도·로그인·실행 오류로 멈추면 이를 알리고, 사용자 의사 없이 다른 도구로 역할을 바꿔 완료한 척하지 않는다.

완료 시 실제 Codex·Claude Code의 담당, 하위 병렬 작업, 활용한 주요 스킬, 검증 결과와 남은 문제를 간결하게 전달한다.

Codex 호출 예: `$dual-ai 이 프로젝트의 로그인 화면과 인증 API를 구현해줘.`

공식 OpenRig: https://github.com/mvschwarz/openrig . 이 스킬은 독립적인 커뮤니티 워크플로이며 OpenRig·OpenAI·Anthropic의 공식 제품이 아니다.
